# Technical demo plan
Planning target: two to three minutes; verify current portal limits first.

Show a real captured run, not the standalone preview animation. Explain the frozen brief and fixed graph. Point to timestamps proving independent roles overlapped. Open one actual generated file and the approval record. Demonstrate the end user's primary action. Show verified cluster/program/provider details for the meaningful Solana integration, once implemented. Finish with the tests, limitations and source/provenance.

A good capture contains: environment/version; real provider usage or response IDs with secrets redacted; artifact hashes; actual user journey; actual chain proof where claimed; a failed/rejected state; what was reused and what the team built.

Current blockers: live runtime verification, meaningful Solana adapter, recorded video and public accessible links. The local rehearsal is useful for explaining the interface, but cannot be used as proof that paid agents or a blockchain transaction ran.
