# Prepare an honest submission draft

Use for the submission lead. Inputs are the frozen brief, accepted discovery artifacts, and build memo. The app and domain files are being generated concurrently and are not available yet. Current portal requirements are unknown unless their content is explicitly supplied.

## Tell one coherent story
Pitch the participant app's specific user, recent decision/problem, current workaround, proposed forecast loop, strongest differentiation hypothesis, and next evidence milestone. Explain why prediction helps and the intended Solana contribution. PredictKit's orchestration is infrastructure, not proof of the participant app's traction or originality.

Separate startup narrative from technical walkthrough. A proposed short script can use estimated timings, but do not label those timings or file formats as current organizer requirements without supplied evidence. Avoid market size, adoption, partnerships, revenue, or team credentials not supported by the input.

## Make the demo observable
Plan the exact question → recorded forecast → history → manual close → human-attested YES/NO/VOID → score/exclusion sequence. For each important action, give the expected on-screen result and evidence to capture. Include one meaningful failure case, such as attempting to forecast after close. Describe this as a recording plan; no video or test has been performed by this worker.

Keep build-sensitive claims PENDING. “The plan specifies local history” is supportable from a memo; “the demo works” requires completed app evidence. A planned Solana adapter is not an on-chain feature. A generated file is not a deployed URL; a fixture is not a live model result.

## Draft for later completion
Provide reusable application answers with explicit missing facts in plain text, not realistic-looking invented URLs. Include the remaining team facts, repository and demo links, original contribution versus reused starter, current form/eligibility checks, and evidence needed to support implementation claims. Preserve supplied license uncertainty rather than asserting permission.

Attach a compact ledger mapping material claims to source locations and evidence status. Where needed, state which completed artifact and operator check should replace PENDING. Use a clear NOT SUBMITTED status and a small final human checklist; this role cannot browse a portal, publish a repository, record video, or submit anything.
