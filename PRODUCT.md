# PredictKit

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Builders first, with traders creating forecasting tools and Solana hackathon teams also included. Confirmed by the owner on 28 September 2026. They want to turn a prediction-market idea into a useful, inspectable first application.

## Product Purpose

One founder brief moves through eight roles, an exact build-memo approval, generated application files and an evidence-backed draft export. The owner values seeing the product and understanding its actual mechanism.

## Operating Context

A local Python standard-library server serves HTML/CSS/JavaScript. Rehearsal uses scripted outputs. The optional live provider sends separate role requests to the configured OpenAI Responses model with a locally configured API key and spend policy. Codex or Claude may edit the downloaded repository; native Codex/Claude worker integrations are not implemented. Local Studio access needs no account or login.

## Capabilities and Constraints

Eight role contracts, eight mapped role skills, two additional operator guides, eleven output artifacts, a three-worker limit, founder approval, saved runs, isolated app preview and draft ZIP export. All role requests use the one configured model. Current workers have no browsing, shell, wallet or execution tools. The forecast reference app is off-chain. The registry compiles to SBF and passes 28 local SVM tests with an executed local demo. The generated app is not connected to it; wallet integration and public deployment remain open. No real-money trading, custody, orderbook or liquidity is implemented.

## Brand Commitments

Retain PredictKit's checkpoint mark, the existing three-theme identity and the successful initial Studio. The owner requests a stronger crypto/trading/Solana feel across the themes and an explanatory landing page before entering the Studio. Solana is the intended chain foundation, not an affiliation or current network connection. The supplied code-first visual identity remains the reference.

## Evidence on Hand

Current capability, live-setup and compiled-program evidence is under evidence/capabilities-2026-09-28/, evidence/live-setup-2026-09-28/ and evidence/solana-execution-2026-09-28/. Agent instructions are in agents/, role assignments in predictkit/skills.py and skills in skills/. No live provider, deployed chain or participant outcome is established by the current evidence.

## Product Principles

- Make the mechanism visible and the first action obvious.
- Distinguish source, rehearsal, real execution and external evidence.
- Let users inspect their files, skills, approval and outputs.
- Keep the first useful prediction flow narrow.
- Preserve keyboard access, readable contrast and reduced-motion behavior as the design develops.

## Open Decisions

Native Codex/Claude providers, separate role models, tool-equipped workers, real trading architecture, authentication, public hosting and a measured workshop release are future capability decisions. This design pass does not implement them.
